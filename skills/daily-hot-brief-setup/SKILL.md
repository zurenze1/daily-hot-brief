# 安装使用者自己的 AI 早报

仓库：https://github.com/zurenze1/daily-hot-brief 。同一个程序支持自定义行业，不要为二奢、汽车、服装、读书分别重做程序或分叉成专用版本。

先读当前仓库 README、AGENTS.md、docs/CONFIGURATION.md 与 docs/VERIFICATION.md。若尚未下载，先按使用者的系统、工作目录和已有安装选择位置，再正常获取官方仓库，保留已有用户改动与运行资料。

## 配置需求

从对话提取已经给出的信息，只补问影响运行的缺项：

- 行业／账号定位和具体受众；
- 想关注与排除的内容，栏目及各自条数、每日总量；
- 当地时区与更新时间，以及是否登录电脑后自动启动；
- 本人可用的模型环境。

二奢、汽车、服装、读书、健康产品等模板只是可编辑的起点；其他行业用自定义配置。数量目标不是硬凑内容的要求，可靠来源不足应报告实际数量。

## 安装与首次运行

- 检查 Node.js >=24.21、端口和网络；按当前 README 用 npm ci --ignore-scripts，不装无关服务或大模型。
- npm run doctor 核本人的模型状态。内置 Codex 需本人正常登录；不要读取、复制、传递或索取认证文件、密码或令牌。不要拿安装 AI 的会话成功当成本机后台模型已可用。
- 默认使用网页设置，或由你根据已确认要求生成一份本人的临时配置，执行 npm run setup -- --file；使用者无需写 JSON。配置、runtime、证据、日志与历史都留其本机并排除 Git。
- 核验符合行业的公开订阅／官方来源和检索方向，不把模板中通用来源当作覆盖了所有行业。抓取失败、仅摘要与全文要如实标明。
- 用本人的模型跑一次真实采集和分析，检查来源实际可读、栏目/数量、具体编辑判断、受众、可拍问题、开场、展开、待补依据和优先级；没有足量内容时交实际数量，不能填示例冒充。
- 若使用其他 AI，按 docs/CONFIGURATION.md 的命令适配器契约配置，并分别测试联网发现与生成。未测试的模型／系统要注明，不能承诺任何 AI 通用。

## 日更与验收

在获准的更新时间启用 schedule。需要开机／登录启动时先审阅 npm run service -- install --dry-run 的平台配置，再在已授权范围安装。已有同项目服务应复用，别创建第二个日更任务；不要改使用者其他工具的自动化。

运行需要电脑、后台、模型与网络可用。服务注册、健康接口、真实模型、实际定时触发和未来每天准点是不同验收层。测试短周期后恢复用户指定时刻，失败不能标完成。

实际打开工具，切栏目/日期，展开完整事实与切口，编辑保存并重启回读；检查公开源码无私人配置和采集数据。交付本机入口、运行目录、实际条数/缺口、自动启动状态、模型/系统验证范围、卸载服务但保留数据的方法。后续换赛道只改其配置，历史保留。
