# 每日热点早报 · 可按行业配置的 AI 选题工作台

同一个程序，给不同的人用。二奢、汽车、服装、读书、健康产品或自定义行业，都由使用者设置自己的关注方向和每日条数。

**把这个仓库链接交给你的 AI，请它先读 [安装 Skill](skills/daily-hot-brief-setup/SKILL.md)，再按你的需求安装。**

> 这是完整本机工具的源码：自动采集 → 核读公开来源 → AI 观点和博主切口 → 保存与编辑 → 定时日更。
> [网页预览](https://zurenze1.github.io/daily-hot-brief/)用于体验虚构内容；完整功能请在自己的电脑运行。
> 本仓库不包含作者已采集的新闻、旧早报、数据库、素材或账号。安装后产生的资料属于使用者自己的本机数据。

## 让 AI 帮你安装

可以连同仓库链接发送：

> 请安装这个项目。先阅读 README 和 skills/daily-hot-brief-setup/SKILL.md。
> 根据我的行业、账号定位和受众，问清楚关注什么、每天收集多少条、栏目怎样分配、几点更新。
> 为我配置来源和我自己的 AI，做一次真实采集与生成测试，并检查自动日更。不要让我手写 JSON，也不要使用作者的数据或账号。

安装 AI 会检测你的系统、Node 和模型。首版内置 **Codex CLI 本人登录**；其他 AI 可以负责安装，自动生成若使用其他模型，则须配置并测试[命令行适配器](docs/CONFIGURATION.md#其他-ai-适配器)。不承诺所有聊天网页都能直接承担无人值守任务。

## 手动启动

需要 Node.js **24.21 或更新版本**、网络、以及自己可用的 Codex CLI 登录。

```sh
npm ci --ignore-scripts
npm start
```

打开终端显示的本机地址（默认 http://127.0.0.1:4897 ）。第一次点“设置行业与日更”，选择或自定义行业，填受众、主题、栏目与条数。可以测试模型连接，再点“立即采集与分析”。无需准备新闻 JSON。

```sh
npm run doctor
```

doctor 只报告安装、登录状态和本机保存位置，不输出认证内容。CLI 不存在或未登录时，请按 [Codex 官方安装与登录说明](https://learn.chatgpt.com/docs/auth)正常安装/登录；不要把登录文件或密钥发到聊天或仓库。

## 每条早报有什么

- 新闻事实、原文链接、原发时间、实际读取范围和生成时间；
- 有依据的编辑判断、具体受众、可拍的问题／切入点；
- 一句口播开场、展开步骤、待补依据、选题优先级及理由；
- 真实来源图（有则显示，缺失留空）；图片出现不代表获得再利用许可；
- 日期／栏目／关键词筛选、优先题、编辑保存、选题 Markdown 导出；
- 历史早报、本次运行进度、资料不足和来源失败原因。

每栏目及每日总量由你设置，合计 1–100 条。数量是目标，不是造新闻的配额。可靠资料不足会显示实际条数与缺口，失败保留旧报。每天最多突出 3 个优先题。

模板只是起点。切换赛道或改条数都只改自己的配置，不需要重新开发一个版本；历史资料继续保留。默认不带任何真实新闻。

## 自动日更与开机运行

在设置里启用“每天自动运行”，选择当地 24 小时的开始生成时刻，完成后更新早报。希望某时刻可阅读时，请按首次实测耗时提前开始；开始时间不冒充交付时间。默认跟随本机时区。后台运行期间会检查到期任务，同一天不会因反复刷新重复消耗模型额度；未完成可在界面查看原因并手动重试。停机后重启会补跑当天，并记录真实时间。

保持 `npm start` 运行即可。需要登录电脑后后台自动启动时，由本人／安装 AI 审阅并使用：

```sh
npm run service -- install --dry-run
npm run service -- install
npm run service -- status
```

移动项目目录前请先卸载旧服务，移动后重新安装；自己的运行数据保留。

支持生成 macOS LaunchAgent、Linux 用户 systemd、Windows 登录任务；各平台实测范围以[验收说明](docs/VERIFICATION.md)为准。卸载自动启动但保留数据：

```sh
npm run service -- uninstall
```

电脑关机、睡眠、断网或模型额度不足会影响运行。开源软件不提供云端常驻算力；希望电脑关闭时也更新，需要另选自己的服务器和模型接入，不能把 GitHub Pages 当成后台。

## 自己的数据放哪里

默认本目录 `runtime/`，可以用 `BRIEF_DATA_DIR` 指定独立目录；`PORT` 改端口。该目录、配置、历史、读取证据与日志已排除 Git。更新源码不会要求上传这些内容。

- `config.json`：自己的需求和运行设置；保存前一版为 `config.previous.json`。
- `editions/`：按日期保存的早报。
- `versions/`：重新生成和编辑前的旧版本。
- `evidence/`：实际读取的公开文字片段及出处。
- `last-job.json`：最近一次运行结果；运行失败不会冒充成功。
- `schedule-attempts.json`：日更去重记录。

工具仅监听本机，未提供公网账号系统。修改操作有同源及 CSRF 检查；抓取阻止私网目标、检查重定向和读取大小。不要直接把本机接口暴露到公网。需要公开分享早报时先核内容权利和个人资料，本工具不会自动把你的日报推到 GitHub。

## 模型、来源与成本

代码 MIT 开源；AI 使用你自己的订阅或你自行配置的适配器额度。不会共享作者账号，也不默认下载本地大模型。

Codex 通过官方 `codex exec` 在独立、只读、临时工作目录执行，禁用 Shell 与多助手，只给本轮需求和选中资料。联网检索仅用于发现公开原文；生成阶段引用必须来自实际取到的 E 编号证据，不能凭空添加来源。

其他适配器必须遵守同一输入／输出契约，是否能联网由其实现决定；来源在安装时需真实测试。网页受限、RSS 失效或没有合适新闻都可能造成缺口。仅取得 RSS 摘要时会明确标注，不冒充完整阅读或独立事实核验。健康产品的研究、监管事实和营销主张应分开判断。
